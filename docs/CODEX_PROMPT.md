# Промпт для Codex

Скопируйте всё, что ниже черты, в задачу Codex (в репозитории основного сайта eyra.ink).

---

Прочитай документ `https://github.com/unleaon-hub/eyra-podcasts-concept/blob/main/docs/CODEX_HANDOFF.md` целиком и следуй ему. Это финальный, утверждённый дизайн раздела подкастов EYRA (версия hub32). Твоя задача — перенести его **один в один** в основной репозиторий сайта eyra.ink и подключить к реальной системе (каталог ИИ-экспертов в Telegram, журнал `eyra.ink/journal`, выпуски = аудиоверсии статей).

Репозиторий прототипа: https://github.com/unleaon-hub/eyra-podcasts-concept  
Живые страницы (source of truth по виду): https://unleaon-hub.github.io/eyra-podcasts-concept/hub.html?v=hub32 и остальные ссылки из handoff.  
Скриншоты приёмки: `docs/screens/` в том же репозитории (390 и 1440).  
Токены: `docs/tokens.json`.

Сделай по шагам из раздела «План внедрения» в handoff:

1. Сначала изучи этот репозиторий сайта: стек, роутинг, шапка, футер, CSS-токены, Manrope, как отдаются статьи журнала и страницы экспертов. Не выдумывай эндпоинты, фреймворк и CMS. Впиши раздел в существующую архитектуру.
2. Предлагаемые маршруты: `/podcasts`, `/podcasts/<expert>`, `/podcasts/topic/<slug>`, `/podcasts/mood/<slug>`, `/podcasts/<expert>/<episode>`, `/podcasts/experts`. Если на сайте уже есть другая конвенция префикса — сохрани сущности, согласуй префикс.
3. Перенеси UI 1:1 (пиксельно близко к прототипу и скриншотам). Можно собрать на компонентах сайта, но не редизайнить.
4. Подключи реальные экспертов и статьи. Аудио: найди существующий TTS/аудиопайплайн и подключись по контракту из handoff. Если его нет — явно пометь TODO, не подставляй фейковые URL.
5. Реализуй плеер с настоящим audio, persist в `localStorage` ключ `eyra.podcast.playback` (схема в handoff), mini-player на всех страницах раздела, back/close/Esc, очередь «Далее» из 6 выпусков и autoplay следующего через 5 с. Рекомендуется Media Session API.
6. В прототипе фильтр «Непрослушанные», таймер сна, шаринг, лайки и ±15 с либо не доведены, либо только UI — в проде их нужно сделать по правилам handoff.

Жёсткие правила, ничего из этого не менять без отдельного решения продукта:

- Не редизайнить и не «улучшать» композицию, палитру, типографику.
- Фон только `#111412`, не осветлять.
- Никаких счётчиков и статистики в интерфейсе.
- В списке колонки одного эксперта — number tiles, не пачка одинаковых лиц.
- Не дублировать заголовок: на мобилке текст на обложке, под фото его нет; на десктопе шоу и плеер — photo-only cover.
- Фильтры только «Все выпуски» / «Непрослушанные» (без «До 8 минут» и без тогглов сетка/список).
- Обводка играющей карточки: 1px `rgba(204,183,143,.38)`, без glow.
- Внутри раздела все переходы остаются в подкастах. Внешние выходы только: «Познакомиться с экспертом» / CTA эксперта → страница эксперта; «Читать статью ↗» → статья журнала; логотип, шапка «Эксперты» и «Блог», ссылки футера — как на основном сайте.
- Шапка раздела: Эксперты, Подкаст, Блог.
- Не возвращать блоки, которые убрали из плеера («Ещё у…», «Похожее», большой end-card, баннер на player).
- Файл `CONCEPT.md` в репозитории прототипа — устаревший ранний бриф; при расхождении верь living prototype hub32 и CODEX_HANDOFF.md.

Приёмка: сверка страниц с `docs/screens/` на 390×844 и 1440×900. В конце дай список маршрутов, как подключены данные/аудио, что осталось TODO, и приложи свои скриншоты рядом с референсом.
