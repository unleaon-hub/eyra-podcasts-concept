# EYRA Podcasts — handoff для Codex (hub32, финальный прототип)

Документ описывает, как перенести утверждённый концепт подкастов **один в один** на основной сайт [eyra.ink](https://eyra.ink/). Проза на русском, имена файлов, классов, токенов и URL — на английском, как в коде.

**Источники правды (в этом порядке):**

1. Живые HTML/CSS/JS страницы прототипа (ниже — ссылки с `?v=hub32`).
2. Этот документ и скриншоты в [`docs/screens/`](screens/).
3. Токены в [`docs/tokens.json`](tokens.json), снятые с `shared.css`.

Файл `CONCEPT.md` в корне репозитория — **ранний бриф**, часть идей в нём устарела (таббар, фильтр «Прослушанные», другие полки). Если CONCEPT.md расходится с прототипом hub32 — ориентируйтесь на прототип.

Стек, роутер, CMS и API основного сайта в этом репозитории **не описаны как факт**. Codex должен сам открыть репозиторий eyra.ink, понять текущую архитектуру и вписать раздел в неё, не выдумывая эндпоинты и не заводя новую UI-библиотеку, если на сайте уже есть токены, Manrope, шапка и футер.

## 1. Цель и правила

- Перенести раздел «Подкаст» **1:1, pixel-faithful**: те же сетки, типографика, отступы, состояния, тексты UI, поведение плеера.
- **Не редизайнить.** Не «улучшать» композицию, не менять палитру, не добавлять счётчики, не осветлять фон.
- HTML/CSS прототипа — визуальный source of truth. Можно переписать на компоненты стека сайта, но результат на 390 и 1440 должен совпасть со скриншотами.
- Подкасты — аудиоверсии статей журнала, голосом экспертов EYRA (каталог ИИ-экспертов в Telegram). Журнал: `https://eyra.ink/journal/`.

## 2. Карта сайта и маршруты

### Прототип → предлагаемые URL на eyra.ink

Пути ниже — **предложение**. Если на сайте уже есть конвенция (например `/journal/...`), согласуйте префикс, но сохраните структуру сущностей.

| Прототип | Query | Предлагаемый путь | Суть |
|---|---|---|---|
| `hub.html` | — | `/podcasts` | Хаб раздела |
| `show.html` | `?e=<expert>` | `/podcasts/<expert>` | Колонка эксперта |
| `topic.html` | `?t=<rubric>` | `/podcasts/topic/<slug>` | Рубрика. `t=new` → «Новое» (`/podcasts/topic/new`) |
| `mood.html` | `?m=<mood>` | `/podcasts/mood/<slug>` | Настроение |
| `player.html` | `?e=<expert>&ep=<episode>` | `/podcasts/<expert>/<episode>` | Full player / страница выпуска |
| `experts.html` | — | `/podcasts/experts` | Сетка колонок экспертов |

Опциональные query плеера, которые прототип читает и затем вычищает из URL через `history.replaceState`:

- `play=1|0` — стартовать сразу / на паузе
- `p=0.0000–0.995` — доля прогресса
- `spd=1|1.25|1.5|2` — скорость
- `t=<rubric>` / `m=<mood>` — контекст очереди «Далее» (следующий из рубрики или настроения, а не только колонки)

Алиас рубрики: `netvorking` → `obshchenie` (см. `catalog.js` `topicBy`).

### Правила навигации

Всё внутреннее движение остаётся **внутри раздела подкастов**: хаб, колонка, рубрика, настроение, плеер, сетка колонок.

**Внешние выходы только такие:**

- «Познакомиться с …» / портрет эксперта / CTA в карточке эксперта внизу колонки / ссылки футера на экспертов → страница эксперта на сайте, сейчас `https://eyra.ink/experts/<slug>/`.
- «Читать статью ↗» → статья журнала, сейчас `https://eyra.ink/journal/<rubric>/<slug>/` (поле `url` выпуска).
- Логотип EYRA / wordmark футера → главная `https://eyra.ink/`.
- Пункт шапки «Эксперты» → `https://eyra.ink/#experts` (как в прототипе).
- Пункт шапки «Блог» → `https://eyra.ink/journal/`.
- Ссылки футера «Блог», «Как это работает», «Вопросы и ответы» — как на основном сайте (`/journal/`, `/#how`, `/#questions`).

Шапка на всех страницах раздела (кроме иммерсивного мобильного плеера): **Эксперты · Подкаст · Блог**. «Подкаст» — текущий раздел (`aria-current="page"`). Не добавлять другие пункты.

Именование: в шапке — «Подкаст»; в hero хаба — eyebrow «Подкасты экспертов»; не писать «Подкасты EYRA» как H1-бренд отдельного приложения.

## 4. Инвентарь компонентов

### Header + мобильное меню

Классы: `.journal-header`, `#journal-menu`, `eyra-chrome.js`. Логотип — золотой знак `assets/eyra-mark.svg` + слово EYRA. Бургер на узкой ширине открывает `<dialog class="journal-menu">`. Поведение меню скопировано с журнала; не упрощать.

На `player.html` при ≤480px шапка сайта **скрыта**, вместо неё `.player-chrome`.

### Кремовый футер EYRA

Класс `.footer`. Крупный wordmark, список 10 экспертов со ссылками на их страницы, утилитарная строка. На десктопе — sticky reveal (`html.footer-reveal`, clip-path, `--footer-cover`), логика в `eyra-chrome.js`. На короткой странице плеера reveal отключается, футер идёт обычным потоком, без пустой полосы. Mini-player не должен перекрывать футер: `bottom: calc(var(--mini) + 12px)`.

### Mini-player

Есть на всех страницах, кроме самого `player.html` (страница и есть плеер; дублировать контролы нельзя).

Состав: крошечная обложка, название, «Имя · рубрика», ±15, play 40px бумажный, таймлайн, скорость, таймер, «Читать статью ↗» (скрыто на узком экране), громкость (декор в прототипе), кнопка раскрыть full player (`data-open-player`).

Состояние поднимается из `localStorage` ключа `eyra.podcast.playback` при загрузке и на `pageshow` (возврат «назад»). Если играет — плашка видна и продолжает «тик» прогресса.

### Full player (`player.html` / `.now-page`)

**Десктоп (≥861):** шапка сайта остаётся. Строка `.player-chrome`: слева ← + хлебные крошки «Подкасты · <рубрика>», справа голая иконка × (без круга, обводки и заливки, хит-зона 40px, цвет `#f2efe8` opacity 80% → 100% на hover). Hero: 2 колонки, обложка **только фото** (без текста на картинке), справа: eyebrow-ссылка на колонку, заголовок ≤3 строк (~40px), хост (аватар ~44px с кольцом акцента, имя + роль в две строки), в середине короткий «О выпуске» (2–3 строки, muted, max-width ~560px), снизу прогресс и контролы на ширину текстовой колонки; «Читать статью ↗» тихо справа в ряду контролов.

**Мобильный (≤480):** иммерсивный. Панель 48px: ←, по центру «Сейчас играет · <короткий rubric>» с ellipsis, ×. Обложка 4:5, скругление 16px. На обложке снизу: маленький eyebrow, заголовок **clamp 2 строки**, приглушённые «Имя · роль». Градиент снизу: `#111412` → прозрачный около 50%. Лица в верхней половине (`object-position` по эксперту). Под обложкой только: прогресс; центрированный транспорт «15 / play ~72px / 15»; второй ряд во всю ширину: скорость, «Таймер», сердце, шаринг. Ссылки «Читать статью» под контролами **нет**. Ниже складки: «О выпуске», «Далее».

**Выход:**

- ← `data-player-back`: `history.back()`, если `document.referrer` того же origin и страница из раздела подкастов; иначе `show.html?e=<slug>` (в проде — `/podcasts/<expert>`).
- × `data-player-close`: тот же referrer, иначе хаб (`hub.html` / `/podcasts`). Воспроизведение **продолжается** в mini-player (сначала `writeStore()`).
- `Escape` на десктопе = close (если не открыто меню).
- Aria: «Назад», «Закрыть плеер».
- Прямая ссылка без referrer: × ведёт на хаб.

**Очередь «Далее»:** 6 выпусков (`rest.slice(0,6)`), сетка 3×2 на 1440, 1 колонка на 390, ссылка «Все выпуски <имя в род. падеже> →» на колонку. Первая карточка может нести hint «Далее через 5 с». Когда прогресс доходит до конца, пауза 5000 мс и переход на первый элемент очереди с `play=1&p=0`. Пауза в эти 5 секунд отменяет переход. Пустая очередь — остановиться на конце (progress 0.995).

Контекст очереди: если URL содержит `t` или `m`, следующие берутся из рубрики/настроения, иначе из той же колонки (`queueFrom` в `catalog.js`).

### Кнопки play

Кремовый круг `--paper`, иконка `--ink`, 64px в hero/десктоп-плеере, ~72px транспорт мобильного плеера, 40px mini. В состоянии playing иконка паузы; заливка может стать `--gold` у `.btn-round-play.is-playing`. Hover: `--paper-h`, лёгкий scale.

### Карточки выпусков

Два семейства:

1. **Number tile** (`.ep-item.has-num`) — список колонки одного эксперта: квадрат с номером, без повторного лица. При hover/active номер сменяется иконкой play / эквалайзером.
2. **Cover / mixed** (`.ep-item.has-cover`) — когда в списке несколько экспертов (рубрика-микс, настроение, «Далее» если микс): мини-обложка портрета + имя в мета-строке.

Общий каркас `.ep-item` / `.mood-ep`: заголовок, мета «N мин» (и имя, если нужно), play, сердце, опционально 2px progress line (`.progress-pip`).

**Активный / играющий:** мягкая обводка `1px solid rgba(204,183,143,.38)`, очень лёгкий подъём фона (≤3%), **без glow и без толстого box-shadow**. Эквалайзер и 2px линия прогресса сохраняются. Не использовать 2px solid gold outline на карточке (это слишком жирно; так было до hub31).

На колонке сначала видно 10 выпусков, далее «Показать ещё» (класс `.is-more`).

Полки хаба: `.card-ep` (горизонтальный rail «Новое» — обложка typo-cover + подпись), `.ep-row` в «Слушают».

### Обложки-герои

- **Шоу, мобильный:** текст на фото (eyebrow «Колонка · Имя», title clamp 2, dek clamp 2), тёмный нижний градиент, лица не перекрывать. Под фото только хост-строка и действия (Слушать / Читать статью / Сохранить / …). Заголовок ниже фото не дублировать (видимый H1 прячется, для a11y остаётся).
- **Шоу, десктоп:** фото-only обложка; title + dek + хост + действия в правой колонке.
- **Рубрика, мобильный:** как плеер — «Рубрика» + название на 4:5 фото, «Слушать подряд» под обложкой; крошки на обложке скрыты, чтобы не повторять название.
- **Рубрика, десктоп:** кино-композиция: текст слева, портрет справа с горизонтальным выходом в фон, без текста, выжженного на лице.
- **Настроение:** не одна обложка, а кластер круглых портретов + заголовок (одобрено, не переделывать под шоу).
- **Хаб «Выпуск дня»:** уже текст поверх большого фото + сайдбар «Далее» из 4 мини-карточек. Автопрокрутка 7 с, стрелки, свайп, пауза на hover.

`object-position` по эксперту — в `tokens.json` (`focus`) и уточнения для 4:5 в конце `shared.css` (hub28/32).

### Бento рубрик

`.bento`: 2 больших портретных тайла (`.big`, `.big.alt`) + мелкие пастельные `<a><b>Короткое имя</b></a>`. Не ставить 10 одинаковых лиц.

### Плашки «Другие рубрики / настроения»

На topic: сетка `.other-topics` / `.topic-tile` с `--plaque`. На mood: `.other-moods` / `.mood-plaque`, текущая с обводкой `.is-on`. На хабе настроения — `.mood-grid .mood`.

### «Разные взгляды»

`.views` / `.view-card`: тема (Деньги, Работа, Чувства), два перекрывающихся аватара, по три выпуска от разных экспертов на одну тему.

### «Слушают»

Нумерованный список `.ep-grid.focus-list` / `.ep-row` из восьми выпусков разных экспертов (в прототипе зашит в HTML хаба).

### Ритуалы (прогноз / карта дня)

`.ritual-row` / `.ritual`: две карточки Веры и Леры с коротким текстом, Слушать + Читать статью.

### Баннер-приглашение

`.blog-invitation` — как на журнале: фото, eyebrow «Личный разговор в Telegram», «Выберите своего эксперта.», 7 дней бесплатно · Без банковской карты.

В прототипе: на хабе/топике/муде CTA «Посмотреть экспертов» ведёт на `experts.html`; на странице `experts.html` — на `https://eyra.ink/#experts`. Сохраните смысл: из раздела подкастов можно попасть в каталог колонок или на основной каталог экспертов / продукт в Telegram. Не выдумывать новые офферы.

Есть также большая expert-card внизу `show.html` (`.catalog-expert-slot`) — портрет, польза, темы, CTA «Познакомиться с …» на `ex.page`. Это внешний выход.

### Фильтры

Только на колонке (`show.html`): **«Все выпуски»** и **«Непрослушанные»**. Фильтр «До 8 минут» и тогглы сетка/список **удалены** (hub31–32) и не должны вернуться.

На 360–390 оба чипа помещаются в одну строку, без переноса, выравнивание влево.

**Важно:** в прототипе клик по фильтру только переключает `.is-on` (см. `player.js`). Реальной фильтрации непрослушанных нет. В проде нужно реализовать (см. §7). Визуал чипов оставить.

### Прочее UI

- Скорость: цикл 1× → 1,25× → 1,5× → 2× (`data-speed`).
- Таймер сна: Выкл / 15 / 30 / 45 мин. В прототипе это только смена лейбла, без реального stop. В проде — остановить audio по таймеру.
- ±15 с: кнопки есть, **обработчика seek в прототипе нет** (прогресс симулируется таймером). Обязательно подключить к реальному `<audio>` / Media Source.
- Шаринг: иконка есть, отдельного JS нет. В проде: Web Share API или копирование канонической ссылки выпуска.
- Лайк / «Сохранить»: только `.is-on` в DOM, без persist. В проде сохранить в storage или аккаунт.
- Пробел — play/pause, если фокус не в поле/кнопке.

## 6. Данные

### Что мокает прототип

- `experts.json` — 10 экспертов (поля ниже).
- `articles.json` — 202 статьи журнала, превращённые в «выпуски» без поля аудио.
- `catalog.js` загружает оба JSON, мапит имя эксперта → slug, строит рубрики и настроения, рендерит списки.
- `player.js` **не играет файл**: интервал `+0.00045` прогресса каждые 400 мс изображает прослушивание.

Это заглушка. Codex подключает реальные данные и аудио.

### Модель (рекомендуемая)

**Expert** — как в `experts.json`:

`slug`, `name`, `genitive`, `role`, `roleShort`, `rubric`, `category`, `eyebrow`, `accent`, `button`, `dek`, `photo` (квадратный кроп для обложек), `portrait` / `portraitSrcset` (для большой карточки), `page` (URL страницы эксперта), `journal` (URL рубрики журнала), `card` `{ titleHtml, title, benefit, description, themes[], cta }`.

**Episode** (из статьи журнала + аудиопайплайн):

| Поле | В прототипе | В проде |
|---|---|---|
| `id` / `slug` | `slug` статьи | стабильный id + slug |
| `title` | да | да |
| `dek` / `excerpt` | `excerpt` | краткий текст «О выпуске» |
| `expertId` / expert | имя «Майя» | лучше `expertId=maya` + связь |
| `rubric` | slug рубрики (есть и `netvorking`) | канонический slug |
| `moods` | нет (эвристика) | явные теги, TODO согласовать с редакцией |
| `duration` | `minutes` (2–15), в UI «N мин»; в плеере секунды = minutes×60 | точная длительность аудио в секундах |
| `audioUrl` | **нет** | URL готового файла; обязателен для плеера |
| `articleUrl` | `url` / `path` | каноническая статья журнала |
| `cover` | портрет эксперта, отдельной обложки выпуска нет | так и оставить, если нет отдельных артов |
| `featured` | редко true | для «Выпуск дня» |

**Rubric:** `slug`, `name`, `short`, `accent`, `plaque` (`button`), опционально `also[]`.

**Mood:** `slug`, `name`, `tint`, `accent`, `plaque`, состав выпусков.

### Контракт аудио (TODO на стороне Codex / бэкенда)

Прототип не содержит и не выдумывает API озвучки. Ожидаемый контракт, который нужно **найти в существующей системе** или завести, если его ещё нет:

## 7. Состояние воспроизведения

Ключ: **`localStorage["eyra.podcast.playback"]`**.

Схема, которую пишет `player.js` `writeStore()`:

```json
{
  "progress": 0.42,
  "playing": true,
  "speedIndex": 0,
  "updated": 1731234567890,
  "expert": "eva",
  "episode": "druzya-kogda-vse-zanyaty-semyami",
  "href": "player.html?e=eva&ep=druzya-kogda-vse-zanyaty-semyami",
  "title": "Как найти друзей, когда все вокруг заняты семьями и детьми",
  "name": "Ева",
  "category": "Друзья и связи",
  "eyebrow": "Связи",
  "role": "Ассистент по нетворкингу",
  "photo": "assets/eva.webp",
  "accent": "#d8ba78",
  "url": "https://eyra.ink/journal/obshchenie/...",
  "duration": 480
}
```

`progress` — доля 0…1 (в прототипе клип до 0.995, пока трек не закончен). `speedIndex` — индекс в `[1, 1.25, 1.5, 2]`. `href` в проде — канонический путь выпуска. `duration` — секунды.

Мини-плеер на любой странице раздела читает это хранилище и продолжает позицию. Закрытие full player обязано записать store до навигации.

**Рекомендация:** Media Session API (`navigator.mediaSession`) — title, artist (эксперт), artwork (фото), seekbackward/forward ±15, play/pause. В прототипе этого нет, в проде желательно.

### «Непрослушанные»

Сделать настоящий фильтр. Предложение: выпуск *прослушан*, если сохранённый прогресс по его id ≥ ~0.9 (или есть отдельный `completed` в store/аккаунте); *начат*, если 0 < progress < 0.9 — в «Непрослушанные» обычно не входит (как «уже начатые»). Уточнить продуктово, но визуально не добавлять бейджи-счётчики. Прогресс по выпускам лучше хранить словарём, например `eyra.podcast.history[episodeId] = { progress, completed, updated }`, не затирая его текущим треком.

### Сохранения (сердце)

Прототип не пишет disk. Предложение: `eyra.podcast.saved = [episodeId, …]` или аккаунт, если он уже есть на сайте. UI — только залитое/пустое сердце, без чисел.

## 8. Жёсткие продуктовые правила

- **Никаких счётчиков и статистики** в UI: не «202 выпуска», не «10 тыс. слушателей», не «N подписчиков». Длительность выпуска («8 мин») — это не статистика, её оставляем.
- Фон **только `#111412`**, без высветления hero «для воздуха».
- **Не повторять одно и то же лицо** пачкой в списке одного эксперта — number tiles. В смешанных лентах чередовать экспертов (`interleaveByExpert`).
- **Не дублировать текст:** заголовок не должен одновременно жить крупно на фото и ещё раз под ним. Крошки «Подкасты · Название» рядом с H1 на десктопе допустимы как навигация; на мобильной обложке рубрики крошки скрыты специально.
- Текста мало: короткие dek, clamp, никаких длинных маркетинговых абзацев в hero.
- Спокойный тон EYRA, без «революций» и tech-блеска.
- Название раздела — «Подкаст» / «Подкасты экспертов», не отдельный музыкальный бренд.
- Не возвращать удалённое: layout toggles, «До 8 минут», «Ещё у эксперта» / «Похожее» на плеере, толстый золотой outline карточки, кружок вокруг × на десктопе, «Читать статью» под мобильными контролами плеера.
